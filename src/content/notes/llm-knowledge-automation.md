LLM에게 대화 기록을 보여주는 것만으로 구조화된 지식 노트를 자동 생성할 수 있다.
단순 요약이 아니라, 기존 지식 네트워크에 연결된 형태로.

## 배경

업무 중 문제를 해결하거나 인사이트를 얻을 때마다 기록하고 싶었지만,
매번 포맷을 맞추고 연결을 찾는 작업이 번거로워 기록이 단절되곤 했다.

[[second-brain]]의 핵심은 기록의 **마찰을 줄이는 것**인데,
LLM이 그 마찰을 제거할 수 있다는 걸 깨달았다.

## 핵심 인사이트

**포맷 규칙 + 기존 노트 목록 = LLM이 연결을 만들어낸다.**

README.md(포맷 규칙)와 NOTE_INDEX.md(기존 노트 목록)를 LLM에게 주면,
대화 기록만으로 기존 지식 네트워크에 편입되는 노트를 자동 생성한다.
[[llm-agents]]의 도구 활용 패턴이 지식 관리에 그대로 적용된다.

> [!insight]
> 좋은 시스템 프롬프트 하나가 매번의 수동 정리를 대체한다.
> [[prompt-engineering]]이 자동화의 품질을 결정한다.

## 왜 중요한가

기존 PKM 도구의 한계는 **입력 마찰**이다.
좋은 구조를 만들어도, 바쁠 때 지키기 어렵다.

LLM 자동화는 이 문제를 구조적으로 해결한다:
- 대화 → 노트: 별도 작성 시간 불필요
- 연결 제안: 기존 노트와의 관계를 LLM이 파악
- 역방향 연결: GitHub Actions가 기존 노트에도 자동 추가

## 적용 방법

1. 문제를 해결하거나 배움이 있을 때 대화 기록을 보관한다
2. `npm run note-index`로 NOTE_INDEX.md를 최신화한다
3. LLM에게 README + NOTE_INDEX + 대화 기록을 전달하고 노트 작성을 요청한다
4. 생성된 파일을 commit & push하면 나머지는 GitHub Actions가 처리한다

[[zettelkasten]]처럼 노트 간 연결이 쌓일수록 시스템의 가치가 커진다.
